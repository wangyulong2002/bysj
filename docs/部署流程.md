# 部署流程（bysj 智慧校园信息管理系统）

> 适用版本：2026-08（uni-app CLI 工程，方案 A）
> 目标：**改一处配置 → 重新构建 → H5 / 小程序全部生效**

---

## 1. 架构总览

| 端 | 技术栈 | 端口 | 部署目标 |
|---|---|---|---|
| 应用后端 | FastAPI（`server/`） | 8000 | 服务器 `uvicorn`（systemd / supervisor） |
| 管理后端 | Django + DRF（`manage/`） | 8001 | 服务器 `runserver`/gunicorn（内网或后台） |
| 应用前端 H5 | uni-app（`uniapp/`） | 8080(dev) | 静态产物 → nginx |
| 应用前端小程序 | uni-app（`uniapp/`） | - | 微信开发者工具上传发布 |
| 数据库 | MySQL 8（3307）、Redis 7（6379） | - | 服务器 Docker / 云数据库 |

---

## 2. 部署前准备

1. **代码同步**：`git clone` 项目到服务器（或 CI 拉取）。
2. **环境变量**：复制 `bysj/.env.example` 为 `.env`，按服务器实际填：
   ```bash
   cp .env.example .env
   ```
   关键项：`MYSQL_HOST/PORT/PASS`、`REDIS_URL`、`JWT_SECRET`、`CORS_ALLOWED_ORIGINS`、`WECHAT_APPID/SECRET`。
3. **依赖安装**：
   ```bash
   # 后端（Python 3.12+）
   cd bysj/server && python -m venv venv && ./venv/bin/pip install -r requirements.txt
   # 前端（Node 16+，uniapp 目录）
   cd bysj/uniapp && npm install --legacy-peer-deps
   ```
4. **数据库迁移**（DDL 权威为 Django migrations）：
   ```bash
   cd bysj/manage && ../server/venv/bin/python manage.py migrate
   ```

## 3. 前端部署（核心：改一处，全端生效）

### 3.1 唯一配置点

前后端 API 地址由**项目根 `bysj/.env` 的 `PUBLIC_BASE_URL`** 统一注入（一次配置全端通用），**只需修改一个文件**：

```ini
# bysj/.env
# FastAPI 对外地址（保留端口）；H5/小程序/签名 URL 直链/Django host 校验全部由此推导
PUBLIC_BASE_URL=http://你的服务器IP或域名:8000
```

| 端 | 读取方式 | 用途 |
|---|---|---|
| FastAPI（`server/`） | `app/core/config.py` 直接读取 | 签名 URL 直链（头像等） |
| H5 / 小程序 | `make h5-build` / `make mp-build` 注入 `VUE_APP_API_BASE` | 请求 API 地址 |
| Django（`manage/`） | `config/settings.py` 读取 | 推导 `ALLOWED_HOSTS` / `CSRF_TRUSTED_ORIGINS` / HTTPS 反代 |
| 管理前端 admin-web | 相对路径 `/admin/api` | 同源部署，无需配置 |

> 读取机制：构建时 Makefile 将 `PUBLIC_BASE_URL` 注入 `VUE_APP_API_BASE`，`uniapp/src/utils/dev.js` 优先使用该值；未注入时回退 `http://127.0.0.1:8000`。`uniapp/.env.production` 仅作为脱离 Makefile 手动构建时的回退，**一般无需修改**。

### 3.2 构建

```bash
cd bysj/uniapp

# H5 产物
npm run build:h5           # 产物: dist/dev/h5/

# 小程序产物
npm run build:mp-weixin    # 产物: dist/dev/mp-weixin/
```

> Node 24 环境需带 `NODE_OPTIONS=--openssl-legacy-provider`（webpack5 兼容），脚本已内置。

### 3.3 H5 部署（nginx）

```nginx
server {
    listen 80;
    server_name your-domain.com;

    root /var/www/bysj-h5;          # dist/dev/h5 内容
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;   # hash 路由无需此段
    }

    # 可选：静态资源缓存
    location /static/ { expires 30d; }
}
```

```bash
sudo cp -r dist/dev/h5/* /var/www/bysj-h5/
sudo nginx -t && sudo systemctl reload nginx
```

### 3.4 小程序部署

1. 微信开发者工具 → **导入项目** → 选择 `dist/dev/mp-weixin/`
2. AppID 填 `bysj/uniapp/src/manifest.json` 中 `mp-weixin.appid` 的值
3. 菜单 **上传** → 填写版本号/备注 → 微信公众平台提交审核 → 发布

> 小程序每次改动（含改 `.env.production`）都需**重新构建并重新上传发布**（微信平台限制）。

## 4. 后端部署（FastAPI + Django）

### 4.1 FastAPI 应用后端

```bash
cd bysj/server
# 方式一：前台运行（测试）
./venv/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8000

# 方式二：systemd（推荐）
# /etc/systemd/system/bysj-fastapi.service
[Unit]
Description=bysj FastAPI
After=network.target

[Service]
WorkingDirectory=/opt/bysj/server
ExecStart=/opt/bysj/server/venv/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
Restart=always

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload && sudo systemctl enable --now bysj-fastapi
```

**CORS 配置**（`bysj/.env`）：
```ini
# 开发期 *
CORS_ALLOWED_ORIGINS=*
# 上线建议白名单（逗号分隔）
CORS_ALLOWED_ORIGINS=http://your-domain.com,https://your-domain.com
```

### 4.2 Django 管理后端

Django 与 FastAPI **共享根 `bysj/.env`**（`manage/config/settings.py` 自动读取），部署只需在 `.env` 里改：

```ini
# bysj/.env
DEBUG=false                        # 关闭调试（必要）
DJANGO_SECRET_KEY=生产随机长密钥     # 生产必填，缺失将拒绝启动
PUBLIC_BASE_URL=http://your-domain.com:8000   # 唯一地址源
```

- **`ALLOWED_HOSTS`**：留空自动从 `PUBLIC_BASE_URL` 推导 host（推荐，改一处全端生效）；也可显式覆盖 `DJANGO_ALLOWED_HOSTS=your-domain.com,127.0.0.1`（逗号分隔）。
- **`CSRF_TRUSTED_ORIGINS`**：HTTPS 反代时留空自动从 `PUBLIC_BASE_URL` 推导；特殊场景用 `DJANGO_CSRF_TRUSTED_ORIGINS` 覆盖。
- **HTTPS**：`PUBLIC_BASE_URL` 以 `https://` 开头时自动启用 `SECURE_PROXY_SSL_HEADER`（Nginx 443 终止 TLS 场景，见 9.4）。
- `DJANGO_DEBUG` 可选，缺省跟随 `DEBUG`。

```bash
cd bysj/manage
../server/venv/bin/python manage.py migrate
../server/venv/bin/python manage.py collectstatic --noinput
../server/venv/bin/python manage.py runserver 0.0.0.0:8001
```

### 4.3 数据库 / 缓存

```bash
# Docker 方式（与开发一致）
docker run -d --name campus-mysql -p 3307:3306 -e MYSQL_ROOT_PASSWORD=xxx mysql:8.4
docker run -d --name redis-stack -p 6379:6379 redis/redis-stack-server:7.4

# 或使用云数据库，并在 .env 中改 MYSQL_HOST/PORT
```

## 6. 更新与回滚

### 更新（改 IP / 域名 / 功能）

```bash
# 1. 改对外地址（唯一配置点，全端生效）
vim bysj/.env            # 改 PUBLIC_BASE_URL
# 2. 重新构建 + 部署
cd bysj/uniapp && npm run build:h5
sudo cp -r dist/dev/h5/* /var/www/bysj-h5/
# 小程序：重新 build:mp-weixin → 上传 → 发布
# 后端改动：systemctl restart bysj-fastapi
```

### 回滚

- **前端 H5**：备份上一版产物目录，`cp -r` 回退即可
- **小程序**：微信公众平台 → 版本管理 → 回退到已发布版本
- **后端**：`git checkout <上一版本> && systemctl restart bysj-fastapi`

## 7. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| H5 页面请求 API 报跨域 | `bysj/.env` 的 `CORS_ALLOWED_ORIGINS` 未包含前端域名，改为白名单后重启后端 |
| 小程序报"域名不合法" | `manifest.json` 已配 `urlCheck:false` 仅对开发工具生效；**线上小程序必须在微信公众平台配置 request 合法域名**（`https://你的域名`），且后端需 HTTPS |
| H5 刷新 404 | nginx 未配 `try_files ... /index.html`（hash 路由可不配） |
| 构建产物仍是旧地址 | 确认 `build:h5` 输出 `--mode production`；`grep 10.0.0.5 dist/dev/h5/static/js/*.js` 可验证注入 |
| 数据库连不上 | 检查 `.env` 的 `MYSQL_HOST/PORT/PASS` 与安全组/防火墙 |
| 登录提示 4011 | `JWT_SECRET` 前后端不一致（多实例部署需统一）；Redis 未启动 |

## 8. 相关文件索引

| 文件 | 作用 |
|---|---|
| `bysj/.env.example` | **唯一配置源模板**（MySQL/Redis/JWT/CORS/微信/Django/对外地址） |
