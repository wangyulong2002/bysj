## 三、缺陷记录（本次发现并修复）

| # | 缺陷 | 根因 | 修复 | 涉及文件 |
|---|---|---|---|---|
| 1 | **幂等并发重复执行**：并发同 `Idempotency-Key` 提交请假落库 10 条（P1-12 违反） | `_db_insert` 用 `ON DUPLICATE KEY UPDATE` 吞掉唯一冲突且业务先于幂等记录提交 | 改为两阶段：业务前 `_db_reserve` 占位（唯一索引防并发）→ 业务 → `_db_complete` 回填；冲突方轮询回查（≤3s）返回首次结果 | `app/core/idempotency.py` |
| 2 | **幂等冲突响应异常**：并发等待超时 `raise ConflictError` 未转 HTTP（BaseHTTPMiddleware 抛异常绕过 FastAPI 异常处理器，客户端收异常） | 中间件直接 raise | 超时返回 4091 JSON 响应（HTTP 409） | `app/core/idempotency.py` |
| 3 | **成绩并发唯一冲突 5000**：并发首次录入同 (student, offering) 触发 `uk_score_student_offering` 未捕获 | INSERT 未捕获 IntegrityError | 捕获转 4091（乐观锁语义） | `app/api/score.py` |
| 4 | **成绩并发死锁 1213**：并发写入同教学班 `FOR UPDATE`+INSERT 交叉锁 | 无死锁重试（B-08 要求） | 路由包装 3 次死锁重试（指数退避） | `app/api/score.py` |

修复后全量回归：FastAPI 173 例 + Django 69 例全部通过。

## 四、双后端联调（T8-2）

验证目标（3.3）：FastAPI 与 Django 读写同一 MySQL 数据一致。

- **P0-1 结构权威**：`manage.py makemigrations --check --dry-run` → **No changes detected**（无漂移）；双端共享表与关键列（`role_code`/`password_version`/`wechat_openid`）一致。
- **Django → FastAPI**：Django ORM 创建学生/教师/院系/班级/课程/当前学期/教学班/排课 → 应用端登录后 `GET /classes/mine` 读到"联调班"、`GET /timetable?week=1` 读到"联调课程" ✅
- **FastAPI → Django**：应用端提交请假（id=50283，status=0 待审批，时长 240min）→ Django ORM 查询同记录 ✅
- 联调数据用后已清理。
